# 바다의 왕 (King of the Abyss) — 게임 기획서

**장르:** 2D 횡스크롤 해양 생존/성장 어드벤처
**플랫폼:** 모바일 웹 (PWA) — 세로 or 가로 모드, 터치 전용
**레퍼런스:** Shark Universe (성장/진화 루프), Hungry Shark Evolution (포만감 압박), Feed and Grow: Fish (티어 포식)
**핵심 한 줄:** 작은 리프 샤크로 시작해 수천 마리를 먹어치우고, 새로운 상어로 진화하며 심해의 왕좌까지 내려간다.

---

## 1. 설계 원칙 (왜 이렇게 만드는가)

| 원칙 | 결정 | 이유 |
|---|---|---|
| 3D 포기, 2D 벡터 | Canvas 2D + 도형 기반 절차적 렌더링 (스프라이트 에셋 0개) | 에셋 제작/토큰 비용 제거. 물고기 1종 추가 = 데이터 1줄 + 색상 팔레트 |
| 입력 2개로 제한 | 드래그 조준 + 부스트 버튼. 공격 버튼 없음 (접촉 시 자동 포식) | 모바일에서 버튼 3개 이상은 한 손 조작 불가 |
| 티어(Tier) 단일 규칙 | 모든 생물에 티어 1~10. `내 티어 >= 상대 티어` → 먹는다 / `상대 > 내 티어` → 맞는다 | "먹을 수 있나?"를 색/크기만 보고 0.2초에 판단 가능. 물고기 종류를 무한히 늘려도 규칙이 안 늘어남 |
| 성장을 2축으로 분리 | 런 내 성장(세션) ↔ 메타 성장(영구) | 한 판만 해도 성장의 쾌감, 계속 해야 할 이유도 동시에 확보 |
| 실시간 대기 없음 | 알 부화는 "시간"이 아니라 "런에서 먹은 양"으로 진행 | 접속 안 하면 못 자라는 구조 = 이탈. 플레이가 곧 진행 |

## 2. 코어 게임 루프

```
스테이지 진입
   ↓
작은 물고기 포식 → 성장 게이지 / 포만감 / 진주 획득
   ↓
성장 단계 상승 → 티어 +1 → 상위 물고기가 먹이로 전환 (해금의 쾌감)
   ↓
포만감 압박 (계속 먹지 않으면 체력 감소) → 멈출 수 없게 만듦
   ↓
보스 조우 → 격파
   ↓
[런 종료] 진주 + 상어알 + 알 성장치 정산
   ↓
메타 화면: 능력치 업그레이드 / 알 부화 / 상어 교체
   ↓
다음 스테이지 (더 깊고, 더 어둡고, 더 큰 것들)
```

**세션 길이 목표:** 1런 = 4~7분. 첫 플레이 3분 내에 "첫 성장 + 첫 알"을 반드시 경험시킨다.

## 3. 티어 시스템 (게임의 심장)

모든 생물은 `tier: 1~10`을 가진다.

| 관계 | 결과 |
|---|---|
| 내 티어 > 상대 티어 | 접촉 즉시 포식. 포만감·성장·진주 획득 |
| 내 티어 == 상대 티어 | 상호 데미지. 물어서 HP를 깎아야 포식 가능 |
| 내 티어 < 상대 티어 | 피격. 티어 차이만큼 데미지 ↑ |
| 특수 플래그 | `shell`(부스트로만 파괴), `toxic`(먹으면 중독), `shock`(접촉 피해, 포식 불가) |

**시각 규칙 (UI 없이 판단하게 만드는 장치)**
- 먹을 수 있음 → 외곽선 없음, 채도 높은 색
- 동급 → 노란 외곽선 + 미세한 맥동
- 못 먹음(위험) → 붉은 외곽선 + 접근 시 화면 테두리 비네트 붉어짐

## 4. 성장 — 2축 구조

### 4-1. 런 내 성장 (Session Growth)
- 성장 게이지 0 → 100 도달 시 **진화 단계 +1** (런 내 최대 +2단계)
- 효과: 티어 +1, 크기 ×1.25, 최대 HP +20%, 흡입 반경 +15%
- 획득량: `성장치 = 먹이 티어 ^ 1.6`
  - T1 ≈ 1 / T2 ≈ 3 / T3 ≈ 6 / T4 ≈ 10 / T5 ≈ 15
  - → T3 상어가 1단계 성장하려면 잡어 100마리 **또는** 동급 15마리. 양쪽 플레이스타일 모두 성립
- 피격으로 성장 게이지는 감소하지 않음(스트레스 방지), 단 진화 단계는 사망 시 초기화

### 4-2. 메타 성장 (영구)

**능력치 업그레이드 — 5종 × 5레벨**

| 능력치 | 효과 /레벨 | 비용 (Lv n) |
|---|---|---|
| 턱 (Bite) | 데미지 +15% | 150 × 2^(n-1) 진주 |
| 지느러미 (Fin) | 이동속도 +8% | 동일 |
| 체력 (Vitality) | 최대 HP +12% | 동일 |
| 폐 (Lung) | 부스트 지속 +20% | 동일 |
| 감각 (Sense) | 흡입 반경 +25%, 암흑 시야 +20% | 동일 |

**상어알 / 부화 (핵심 수집 요소)**
- 획득 경로: 보스 첫 격파 1개 / 스테이지 숨겨진 보물 3개 / 일일 미션
- 부화 방식: **실시간 대기 없음.** 알을 "부화 슬롯"에 넣으면 런에서 먹은 포만감의 20%가 알에 축적 → 100%에서 부화
- 중복 알 → 해당 상어 **각성 레벨 +1** (기본 스탯 +5%, 최대 +5)

## 6. 스테이지 구성 (6개)

각 스테이지는 자유 탐험형 오픈 구역 (월드 약 6000 × 2500px). 클리어 조건 = ① 목표 티어 도달 ② 보스 격파.
**3성 조건:** 보스 격파 / 피격 3회 이하 / 숨겨진 보물 3개 발견.

### 스테이지 1 — 햇살 연안 ☀️
- 수심 0~30m, 밝은 청록. 적정 티어 T3
- **먹이:** 멸치(T1·무리), 새우(T1), 흰동가리(T1·도주), 해마(T1), 고등어(T2·무리도주), 전갱이(T2·무리), 복어(T2·`toxic`), 불가사리(T2·정적), 농어(T3·도주), 가오리(T3), 게(T3·`shell`), 바다거북(T3·`shell`)
- **위험:** 해파리(`shock`), 어선 그물(접촉 시 2초 속박)
- **보스:** 거대 바라쿠다 (T4, HP 600)
- 포만감 소모 ×1.0 — 튜토리얼 구간

### 스테이지 2 — 산호 정원 🪸
- 수심 30~80m, 색채 폭발. 적정 티어 T4
- **먹이:** 비늘돔(T2), 나비고기(T2), 청줄놀래기(T2), 쏠배감펭(T3·`toxic`), 돌돔(T3), 오징어(T4·먹물로 시야 차단), 곰치 치어(T4·추격), 상어 치어(T5·추격), 대왕조개(T5·`shell`·고득점)
- **위험:** 성게(정적 가시), 말미잘(끌어당김), 좁은 산호 통로(압사 위험)
- **보스:** 대왕 곰치 (T6, HP 900) — 굴에 숨어 기습, 위치 예측 플레이
- 포만감 ×1.1

### 스테이지 3 — 난파선 해구 🚢
- 수심 80~250m, 어둡고 좁음. 적정 티어 T5
- **먹이:** 정어리(T3·대규모 무리), 노랑가오리(T3), 아귀(T4·유인등으로 유혹), 붕장어(T4), 참치(T5·초고속 도주, 부스트 필수), 황새치(T5·돌진 반격), 귀상어(T6·추격), 청새리상어(T6·추격)
- **위험:** 기뢰(폭발), 낚시줄, **암흑** — 시야 반경 제한(감각 업그레이드로 완화)
- **보스:** 무법자 백상아리 (T7, HP 1200)

### 스테이지 4 — 빙하 해역 🧊
- 수심 0~150m, 창백한 푸른색 + 유빙 천장. 적정 티어 T6
- **먹이:** 청어(T4·무리), 대구(T4), 연어(T5), 왕게(T5·`shell`), 바다표범(T6·민첩 도주), 펭귄(T6·도주), 바다코끼리(T7·탱커 추격), 레오파드바다표범(T7·추격)

- **보스:** 범고래 알파 (T8, HP 1600) — 음파 기절 + 수면 돌진 콤보

### 스테이지 5 — 심해 열수구 🌋

- **먹이:** 발광 플랑크톤(T5·무리), 심해새우(T5), 풍선장어(T6), 도끼고기(T6), 흡혈오징어(T7), 그린란드상어(T7), 산갈치(T8), 심해 만타(T8)

- **보스:** 크라켄 (T9, HP 2200) — 촉수 8개를 개별 파괴해야 본체 노출
- 포만감 ×1.4

### 스테이지 6 — 왕좌의 해구 👑 (엔드게임)
- 적정 티어 T8
- **먹이:** 전 스테이지 **엘리트 변종** (티어 +1, 전원 공격적, 체력 ×2)
- **위험:** 소용돌이, 고대 유적 함정
- **보스:** 메갈로돈 (T10, HP 3000) — 3페이즈 + 엔딩 연출 → **바다의 왕** 칭호

## 7. 전투 / 수치 설계

**플레이어 수치**
```
최대 HP      = 100 × (1 + 0.15 × (상어티어 - 3)) × (1 + 0.12 × 체력레벨)
기본 속도    = 상어별 180~280 px/s × (1 + 0.08 × 지느러미레벨)
물기 데미지  = 10 × (1 + 0.15 × 턱레벨) × 상어 배수
흡입 반경    = 크기 × 1.2 × (1 + 0.25 × 감각레벨)   ← 이 반경 안의 하위 티어는 자동 흡입
```

**포만감 (Hunger) — 압박 장치**
```
최대 100, 초당 1.4 × 스테이지배수 감소
포만감 0 → 초당 최대 HP의 3% 감소
포식 1마리 회복량 = 먹이티어 × 4
```
→ 스테이지 1에서 T1 잡어만 먹으면 약 3초에 1마리는 먹어야 유지. "멈추면 죽는다"는 리듬 확보.

**부스트 (유일한 액션 버튼)**
```
스태미나 100 / 사용 시 초당 35 소모 / 미사용 시 초당 18 회복
속도 ×2.2, 충돌 데미지 = 물기 ×2.5 + 0.8초 스턴
용도: ① 추격·도주 ② shell 파괴 ③ 상위 티어 적 스턴 후 탈출 ④ 보스 경직 유발
```

**피격**
```
상위 티어 접촉 지속 피해 = (적티어 - 내티어) × 8 /초
피격 시 0.8초 무적 + 넉백 (연속 사망 방지)
```

**보스전 설계 (3페이즈 공통 골격)**

| 페이즈 | HP 구간 | 패턴 |
|---|---|---|
| 1 | 100~66% | 돌진 (0.7초 붉은 예고선) |
| 2 | 66~33% | 돌진 + **잡어 무리 소환** |
| 3 | 33~0% | 돌진 + 소환 + 광역기 (소용돌이/음파) |

- **약점 창(窓):** 돌진 직후 1.5초 경직 → 이 타이밍에 물면 데미지 ×2. 보스전이 "회피 후 반격" 리듬이 된다
- **소환 패턴이 디자인의 핵:** 보스가 소환한 잡어를 플레이어가 먹어서 포만감·HP를 회복한다. 즉 소환은 위협이면서 동시에 생명줄 → 장기 보스전에서 포만감 고갈로 억울하게 죽는 일을 방지

## 8. 조작 (모바일 최적화)

```
┌─────────────────────────────────┐
│ ❤️████░░  🍖███████░  👑T4  💎1,240│  ← HUD (상단, 최소화)
│                                 │
│                                 │
│          🦈                     │
│                                 │
│                                 │
│  ◉                        [ 🚀 ]│  ← 좌: 플로팅 조이스틱 / 우: 부스트
└─────────────────────────────────┘
```

- **이동:** 화면 왼쪽 절반 어디든 터치 → 그 지점에 조이스틱 생성, 드래그 방향으로 유영. 손가락을 떼면 관성으로 감속
- **포식:** 버튼 없음. 흡입 반경에 들어온 하위 티어는 자동 섭취
- **부스트:** 오른쪽 하단 고정 버튼 (반경 72px, 엄지 도달 범위 내)
- **성장 연출:** 진화 시 0.4초 슬로모션 + 화면 전체 파동 + 크기 확대 → 성장을 "느끼게" 만드는 핵심 피드백
- 세로 모드 기준 설계, 가로 모드는 시야 확대 보너스

## 9. 아트 / 사운드 방향

- **스타일:** 플랫 벡터 + 2~3색 그라디언트. 모든 생물은 Canvas Path(타원 + 삼각 지느러미 + 꼬리 베지에)로 **절차적 생성**
- **생물 1종 정의 = 데이터 1줄:** `{ id, name, tier, bodyColor, finColor, bodyRatio, behavior, flags }` → 물고기 50종을 에셋 없이 구현
- **애니메이션:** 꼬리 사인파 흔들림(속도 비례), 몸체 미세 스케일 펄스. 프레임 애니메이션 0장
- **배경:** 3레이어 패럴랙스 (원경 수중광 / 중경 암초 실루엣 / 근경 부유물 파티클)
- **사운드:** 효과음 8종 + 스테이지별 앰비언트 1개 (포식 '뽁', 부스트 '쉬익', 피격, 성장 '웅—', 보스 등장, UI)

**빠진 것:** 해역 4~6, 보스 3체, 상어 4종, 미션·3성 평가, 숨겨진 보물, 튜토리얼

### 기획값과 달라진 부분 (실측으로 조정)

| 항목 | 기획 | 데모 | 이유 |
|---|---|---|---|
| 시작 티어 | T3 | **T2** | 포식 조건이 `내 티어 > 상대 티어`라 T1 로 시작하면 먹을 수 있는 대상이 공집합이 된다 |
| 진화 단계 | — | T2→T3→T4→T5 (4단계) | 1회 플레이에서 성장 전체 호를 보여주기 위함 |
| 월드 크기 | 6000 × 2500 | **3200 × 1700** | 세로 390×844 뷰포트가 원안의 3%만 비춰 화면이 텅 비었다 |
| 개체 밀도 | 명시 없음 | 활성 사각형 내 **170마리** | 화면 평균 30~40마리에서 "바다가 살아있다"는 느낌이 나온다 |
| 회피 반경 | 명시 없음 | 150px (기획 의도 270) | 270px 는 세로 화면 높이의 1/3 이라 플레이어 주변이 통째로 비었다 |

### 렌더링에서 배운 것

- **생물 피치는 ±32°로 제한해야 한다.** 속도 벡터를 그대로 각도로 쓰면 수직으로
  헤엄치는 물고기가 "세워둔 알약"으로 보인다. 횡스크롤 2D의 표준 처리
- **몸통 비율은 가로:세로 ≈ 2.4:1.** 1.2:1 이면 물고기가 아니라 달걀이다
- **채도를 올려야 수중 배경에서 분리된다.** 회청색 계열은 파란 물속에서 사라진다.
  청록 / 노랑 / 올리브 / 보라 / 주황처럼 배경과 색상환에서 떨어진 색을 쓴다
- **위험 비네트는 최대 알파 0.2.** 0.42 는 화면 전체를 보라색으로 덮는다
- 스폰은 원형 링이 아니라 **뷰포트 사각형 기준**이어야 한다. 세로 화면은
  가로 195px / 세로 422px 로 비대칭이라 원형 링은 가로 방향 개체를 화면 밖 360px 에 만든다

### 아직 사람이 확인해야 하는 것

자동 테스트(먹이 추적 오토파일럿)로 검증한 것은 **동작**이지 **재미**가 아니다.
다음은 직접 플레이로만 판단할 수 있다:

1. **성장 속도** — 오토파일럿 기준 75초에 최종 단계 도달. 사람은 더 느리겠지만
   런 목표(4~7분)보다 빠를 가능성이 높다. 임계값(30/72/150) 조정 필요 여부
2. **포만감 압박의 강도** — 1.2/초가 쫓기는 느낌인지, 성가신 느낌인지
3. **부스트 쓸 일이 충분한지** — 현재 용도는 추격 / 게 껍질 / 포식자 밀어내기 3가지
4. **동급 전투(물기)가 재미있는지** — 아니면 그냥 번거롭기만 한지

### 보스 — 거대 바라쿠다 (T6, HP 500)

티어 4 도달 시 등장. 상태기계로 구현했다.

| 상태 | 길이 | 내용 |
|---|---|---|
| intro | 2.0초 | 경고 배너 + 접근 |
| idle | 0.8~1.6초 | 간격을 재며 맴돌다 패턴 선택 |
| telegraph | 0.7초 | **빨간 점선으로 돌진 경로 예고** — 피할 수 있는 창 |
| dash | 0.55초 | 예고한 방향으로 640px/s 돌진 |
| **stagger** | **1.7초** | 경직. 노란 고리 표시, 물기 데미지 ×2, 접촉 피해 없음 |
| summon | 0.9초 | 잡어 7~10마리 소환 (페이즈 2+) |
| vortex | 2.4초 | 끌어당김 — 부스트로 벗어난다 (페이즈 3) |

페이즈는 HP 66% / 33% 에서 전환되고, 페이즈마다 패턴 풀이 늘어난다.

**소환 패턴이 설계의 핵심이다.** 보스가 부른 잡어를 플레이어가 먹어 포만감과 체력을
회복한다. 위협이 곧 생명줄이라, 장기전에서 굶어 죽는 억울한 패배가 없다.

### 메타 성장

- **진주**: 포식 1마리 = 티어만큼, 보스 격파 +150
- **능력치 5종 × 5레벼**: 비용 80·160·320·640·1280 (기획의 150×2^n 에서 하향 — 1런 수입이 150~300이라 첫 업그레이드까지 너무 멀었다)
- **상어알**: 보스 첫 격파 시 1개. 부화기에 넣으면 **런에서 먹은 물고기 1마리당 +2%**, 100%에서 부화 (실시간 대기 없음 — 기획 의도 그대로)
- **상어 3종**: 리프 샤크(균형) / 톱상어(껍질 파괴, HP +25%, 속도 −8%) / 귀상어(흡입 ×1.8, HP −10%)
- **저장**: localStorage. 손상된 데이터는 조용히 초기화한다

### 구현에서 배운 것

- **세로 화면에서 보스 크기는 화면 폭의 1/3을 넘으면 안 된다.** 처음 len 180 으로
  만들었더니 화면 밖으로 넘쳐 전체 실루엣이 안 보였다. 140 으로 줄이고,
  보스전 동안 카메라가 플레이어와 보스의 중간을 30% 비중으로 따라가게 했다
- **메뉴를 띄울 때 게임 HUD 를 감춰야 한다.** 반투명 오버레이 뒤로 체력바가 비쳐 보였다
- **보스 체력바는 기존 HUD 아래로 내려야 한다** (top +124px)

### 아직 사람이 확인해야 하는 것

**보스 난이도가 검증되지 않았다.** 오토파일럿 두 번의 결과가 정반대였다 —
한 번은 140 중 3 남기고 클리어, 한 번은 물고기를 더 많이 먹고도 페이즈 1에서 사망.
최적 플레이를 하는 봇조차 결과가 갈리므로 자동 테스트로는 난이도를 정할 수 없다.
1차 결과를 보고 접촉 피해 14→11, 경직 1.5→1.7초로 한 번 완화했지만 그 이상은
사람이 해보고 정해야 한다.

조정 레버는 세 개다:
1. `BOSS.hp` (500) — 전투 길이
2. `BOSS.contact` (11) — 실수 1회의 대가
3. 경직 길이 (1.7초) + `BOSS.staggerMul` (2.0) — 제대로 피했을 때의 보상 크기

## 부록 4. 보스 부위 판정 (4차)

### 문제

보스 판정이 원 하나였다. 꼬리를 물든 입으로 돌진하든 접촉 피해가 똑같았다.
그래서 보스전이 "경직을 기다렸다 때리고, 나머지 시간엔 아무것도 안 한다"가 됐다.
위치를 잡을 이유가 없으니 공간을 쓰는 플레이가 사라졌다.

### 해결 — 진행 방향 기준 3분할

보스의 진행 방향 벡터에 플레이어 위치를 투영해 `u = -1(꼬리) ~ +1(머리)` 을 구하고
세 구간으로 나눈다.

| 부위 | u | 내가 받는 피해 | 내가 주는 피해 |
|---|---|---|---|
| 머리 | > 0.3 | **100%** | ×0.6 |
| 몸통 | -0.3 ~ 0.3 | 50% | ×1.0 |
| 꼬리 | < -0.3 | **0%** | ×1.3 |
| (경직 중) | 전 부위 | 0% | ×2.0 (부위 배수와 곱) |

실측 1회 물기 기준: 머리 7 주고 10 받음 / 몸통 11 주고 5 받음 / 꼬리 14 주고 **0** 받음.
최적은 경직 + 꼬리로 ×2.6.

**꼬리가 공짜는 아니다.** 보스는 idle 상태에서 플레이어 방향으로 계속 움직이므로
머리가 자연히 플레이어를 향한다. 꼬리를 잡으려면 실제로 헤엄쳐 돌아야 한다.

### 읽히게 만들기

규칙이 있어도 보이지 않으면 없는 것과 같다. 세 가지로 알린다.

1. 보스 몸에 **부위 발광** — 머리 빨강, 꼬리 초록 (경직 중에는 전부 안전하므로 숨김)
2. 물 때마다 **부위 이름이 떠오른다** — "머리"(빨강) / "몸통"(노랑) / "꼬리"(초록)
3. 보스 체력바 아래 한 줄: "꼬리는 안전하다 · 머리를 조심해라"

튜토리얼 없이 가르치는 방식이다. 한 번 물어보면 규칙이 드러난다.

### 부수 효과

난이도가 **숫자를 낮추지 않고** 내려갔다. 2~3차에서 보스가 너무 어려운 것 같다고
판단했지만 자동 테스트로 확정할 수 없어 보류했는데, 부위 판정은 "잘하면 안 맞는다"는
방향으로 여유를 만든다. 체력이나 피해량은 그대로 뒀다.

## 부록 5 — 실기기에서 드러난 것 (2026-10-11)

헤드리스 검증으로는 나오지 않고 아이 폰에서 찍은 스크린샷으로만 드러난 세 가지.

### 1. 브라우저 자동 다크모드가 UI 색을 덮어쓴다

폰에서는 "모험 시작" 버튼이 금색이 아니라 검붉은 색이었고 체력바도 거의 검정이었다.
캔버스와 이미지는 멀쩡한데 CSS로 칠한 것만 어두웠다 — 삼성 인터넷·크롬의
**웹페이지 자동 다크모드**가 밝은 CSS 색을 뒤집는 전형적인 증상이다.

`<meta name="color-scheme" content="dark">` 와 `:root{color-scheme:dark}` 로
"이미 어두운 화면"이라고 선언하면 브라우저가 손대지 않는다.

**교훈:** 헤드리스 크로미움은 이 기능을 켜지 않으므로 끝까지 재현되지 않는다.
어두운 테마의 웹 게임은 처음부터 `color-scheme` 을 선언하고 시작해야 한다.

### 2. 카메라 여유(CAM_OVER)가 해저 밑을 드러냈다

가장자리에서도 상어가 중앙에 남도록 월드 밖 300px 까지 카메라를 허용했는데,
아래쪽에서는 그려둔 해저가 위로 밀려나고 그 밑으로 **원경 배경이 드러나
바다가 두 겹으로 보였다**. 원경은 화면 높이에 맞춰 고정으로 깔리기 때문이다.

아래쪽 여유만 `CAM_UNDER = 110` 으로 따로 떼고, 바닥 칠을 월드 아래 420px 까지
늘려 그 여유를 덮었다.

**실패한 1차 시도:** 플레이어가 내려갈 수 있는 한계를 `WORLD.h-24` → `-56` 으로
올렸더니 **게·대왕조개·성게를 건드릴 수 없게 됐다.** 이 셋은 흡입 대상이 아니라
접촉 판정(`p.len*0.46 + def.len*0.34` ≈ 21~27px)으로만 잡히는데,
바닥 생물은 `WORLD.h-14` 까지 앉으므로 42px 이 벌어져 영원히 닿지 않는다.
카메라만 고치고 플레이어 제한은 되돌렸다.

### 3. HUD 가 작았다

막대 9px·라벨 8.5px 는 폰에서 읽히지 않는다. 15px·11.5px 로 키우고
안쪽 그림자 + 상단 하이라이트로 유리관처럼 보이게 했다.

**교훈:** 390×844 스크린샷을 데스크톱에서 2배로 확대해 보면 작은 글씨도 읽힌다.
실제 기기 크기로 봐야 판단이 선다.

## 부록 6 — 칩튠 BGM (2026-10-11)

효과음 13개와 물소리 베드만 있고 배경음악은 없었다. 레트로 칩튠을 택했다.

### 구성

NES 3채널을 그대로 흉내 냈다. **오디오 파일은 0개**, 전부 코드로 연주한다.

| 채널 | 음색 | 역할 |
|---|---|---|
| 리드 | 사각파 | 멜로디 |
| 베이스 | 삼각파 | 루트 + 옥타브 바운스 |
| 드럼 | 노이즈 | 킥(사인 피치다운) · 스네어(밴드패스) · 하이햇(하이패스) |

악보는 16분음표 한 칸짜리 토큰 배열이다. `'A4'` 는 음을 치고 `'.'` 은 앞 음을
이어간다. 채널마다 길이가 달라도 되고 각자 자기 길이로 돌기 때문에
드럼은 16칸만 쓰고 멜로디는 64칸을 쓴다.

### 곡

| 화면 | BPM | 진행 | 분위기 |
|---|---|---|---|
| 타이틀 | 140 | Am F C G | 모험의 시작 |
| 기지 | 96 | C Am F G | 느리고 성기게 |
| 햇살 연안 | 128 | C G Am F | 밝고 통통 |
| 산호 정원 | 136 | F C Dm G | 더 밝고 장난스럽게 |
| 난파선 해구 | 112 | Dm A# F A | 어둡고 느리게 |
| 보스 | 152 | Em C D B | 빠르고 몰아치게 |

### 스케줄링

`setInterval(25ms)` 로 **120ms 앞까지 미리 예약한다**. 타이머 지터를 박자에
묻히지 않게 하는 표준 기법이다. 탭을 전환했다 돌아오면 `next` 가 과거에
머물러 수백 칸이 한꺼번에 예약될 수 있으므로, 밀렸으면 현재 시각으로 다시
맞춘다 (5초 밀린 상황을 흉내 내 1칸만 예약되는 것을 확인했다).

### 믹스

- BGM 은 전용 게인 0.22 를 거쳐 마스터로 — 효과음 밑에 깔린다
- 물소리 베드는 0.055 → **0.022** 로 낮췄다. 칩튠과 겹치면 탁해진다.
  해역별 필터 컷오프(180/320/420Hz)는 그대로 둬서 깊이감은 남는다
- 음소거는 마스터 게인이므로 BGM 도 같이 꺼진다

### 들어보는 법

`OfflineAudioContext` 로 각 곡을 렌더해 WAV 로 뽑을 수 있다.
`?debug` 로 열면 `window.__TRACKS` / `__emitStep` 이 노출된다.
렌더 스크립트로 음 토큰 오타(주파수 0 = 무음)와 클리핑도 함께 검사했다.

**주의:** 산호 정원 드럼을 처음에 17칸으로 써서 64칸 멜로디와 어긋났다.
채널 길이는 반드시 멜로디 길이의 약수여야 한다.

## 부록 7 — 흐름 · 지도 · 도감 · 해역 장치 (2026-10-13)

| 영역 | 내용 |

### 설계 메모

- **장치 = 데이터 한 줄 + 항목 하나.** 해역의 `hazards:['net']` 이 켜고, 지도·입장 안내가
  `HAZARDS[k].icon/name/tip` 을 그대로 읽는다. 해역 4~6 을 만들 때 코드가 아니라 데이터가 늘어나게
- **기뢰는 위협이자 무기다.** 보스가 들이받으면 보스가 크게 다친다 — 보스전 소환 잡어(위협이 곧
  생명줄)와 같은 원리를 지형에 적용했다
- **도감 그림을 새로 그리지 않는다.** 전역 `ctx` 를 잠깐 바꿔 `drawCreature` 를 작은 캔버스에 돌린다.
  스프라이트가 없으면 도형으로 나오므로 Canvas 폴백 원칙과도 맞는다

### 이번에 배운 것

- **메뉴 화면 뒤에서도 render 는 돈다.** 런 상태를 쓰는 그리기(그물)를 런 밖에서 부르면 매 프레임
  예외로 화면이 멈춘다. 장치는 런 시작 때 켜는 `G.hz.on` 으로 막았다
- **`python -m http.server` 는 캐시 헤더가 없다.** 브라우저가 옛 JS 를 계속 써서 고친 게
  안 고쳐진 것처럼 보였다. 주소에 `&v=<시각>` 을 붙인다
- 지도 배경을 노드마다 두 색으로 끊으면 줄무늬가 진다. 노드당 한 색이면 부드럽게 이어진다

### 아직 사람이 확인해야 하는 것

- 장치 세기 (그물 2.2초 / 먹물 최대 어둡기 0.93 / 기뢰 10~24 피해, 보스 −90)
- 메달 기준 (10/40/100, 티어 4+ 3/10/30)

### 추가 (2차) — 보스 굴

진화 3단계에 보스를 바로 소환하던 것을 **찾아가는 방식**으로 바꿨다.
맵 반대편에 붉게 맥동하는 굴(보스 실루엣)이 열리고, 화면 밖이면 가장자리 화살표가 거리와 함께
방향을 알려준다. 굴에 240px 안으로 들어가면 보스가 굴에서 나온다.

- **언제 싸울지를 아이가 고른다.** 더 먹고 4단계 성체가 된 뒤에 가도 된다 — 예전엔 성체가
  보스전 도중에만 될 수 있어서 마지막 성장 단계가 의미가 없었다
- 무한정 미룰 수는 없다 — 포만감은 계속 줄고, **90초가 지나면 보스가 직접 온다**
- 넓은 맵을 가로지를 이유가 생긴다
- 화살표는 어둠 위에 그려서 난파선 해구에서도 보인다

타이틀 상어 그림에 CSS 헤엄 애니메이션(6초 주기, 둥실 떠다니다 앞으로 확 달려듦)을 넣었다.
캔버스 상어가 겹쳐 보여 그림으로 바꾸면서 멈춰 있던 것이다.

부록 12의 버블 아쿠아리움 기지에 맞춰 나머지 메뉴도 밝게 바꿨다 (시안 `demo/_mock/menus.html`, 커밋 안 함). 기능·저장은 그대로.

- **도감 상세**: 아래 띠 → 가운데 팝업. 작은 수조에서 둥실, 먹은 수 · 메달 · 황금 숫자 칸, 설명은 노란 쪽지, 다음 메달까지 남은 수. 바깥이나 ✕ 로 닫는다.

- **바다 지도**: 지도는 그대로, 머리·정보판을 흰 카드로, "잠수 시작"을 노란 통통 버튼으로. 지도 CSS가 뒤에 있어 `#mapScreen` 으로 덮어씀.

## 부록 23 — 상어를 다 모은 뒤 남은 알 (2026-10-25)

버그: 알에서 나올 상어를 다 모았는데 기지 부화기 배지는 "알 3", 정산은 "부화기에 넣어라" — 막상 부화기에는 넣을 곳이 없었다.
- 다 모은 뒤엔 부화기에서 **남은 알을 진주로 바꾼다** (알 1개 = ◈300, `EGG_PEARLS`). 배지는 "◈"로 바뀌고, 바꾸면 사라진다.
- 정산 메시지도 "상어알 획득 — 부화기에서 진주로 바꿀 수 있어요"로. 비밀 고블린 상어는 알에서 안 나오므로 문구를 "알에서 나올 상어를 다 모았어요"로 정확히.
- 확인: 상어 7종 보유 + 알 3개 → 배지 ◈, 바꾸기 → 진주 +900 · 알 0 · 배지 사라짐, 콘솔 에러 0.
