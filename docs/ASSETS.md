# 이미지 에셋 규격

게임은 **이미지 없이도 완전히 동작한다.** 모든 생물과 배경에 Canvas 절차적 렌더링이
폴백으로 들어 있다. 이미지는 그 위에 얹는 교체 레이어다.

- 이미지가 **없으면** → Canvas 렌더링. 네트워크 요청 0건
- 이미지가 **있으면** → 이미지 렌더링
- 이미지 로딩이 **실패하면** → 콘솔 경고 1줄 + Canvas 렌더링으로 자동 대체. 게임은 멈추지 않는다

**이미지는 보이는 것만 바꾼다.** 충돌 판정, 이동 속도, 성장 수치, 먹이 판정, 저장 데이터는
이미지 유무와 무관하다. 스프라이트 크기는 생물의 `len` 값에서만 계산된다.

---

## 1. 넣는 방법

1. 파일을 `demo/assets/<분류>/<파일명>` 에 넣는다
2. `demo/index.html` 의 `ART` 객체에서 해당 줄의 주석을 푼다

```js
const ART = {
  'fish.clown': 'fish/clown.png',      // ← 주석을 풀면 이 그림이 쓰인다
};
```

`ART` 에 등록되지 않은 파일은 로드하지 않는다. 그래서 등록 전까지는 요청이 0건이고,
404 가 쌓이지 않는다.

---

## 2. 공통 규칙

| 항목 | 값 |
|---|---|
| 포맷 | PNG (투명 배경) · 배경 이미지만 JPG 허용 |
| 방향 | **모든 생물은 오른쪽(→)을 보도록** 그린다. 왼쪽 이동은 코드가 뒤집는다 |
| 중심 | 이미지의 **정중앙이 생물의 중심**이자 충돌 기준점 |
| 여백 | 상하좌우 여백을 최소화한다. 여백이 많으면 작게 보인다 |
| 색 공간 | sRGB |

### 생물 스프라이트의 가로폭 규칙

**이미지 가로폭 = 게임 내 몸길이(len) × 1.5**

즉 주둥이 끝부터 꼬리 끝까지(지느러미 포함) 전체가 이미지 가로를 꽉 채우게 그린다.
몸통만 그리고 여백을 두면 실제보다 작아 보인다.

세로 비율은 자유다. 코드가 이미지의 원본 비율을 그대로 유지한다.

## 3. 파일 목록

### 3-1. 타이틀 (`assets/title/`)

| 키 | 파일 | 권장 크기 | 투명 | 비고 |
|---|---|---|---|---|
| `title.bg` | `background.png` | 1920×1080 | 불필요 | 화면을 꽉 채움(cover). 중앙 40%는 제목·버튼이 덮으므로 비워둘 것 |
| `title.shark` | `shark.png` | 900×600 | **필요** | 타이틀 주인공 상어. 오른쪽을 봄 |

### 3-2. 해역 배경 (`assets/stage/`)

| 키 | 파일 | 권장 크기 | 투명 | 비고 |
|---|---|---|---|---|
| `stage.shore` | `shore.png` | 2048×1152 | 불필요 | 원경. **좌우 끝이 이어지면** 끊김 없이 반복됨 |
| `stage.coral` | `coral.png` | 2048×1152 | 불필요 | 〃 |
| `stage.wreck` | `wreck.png` | 2048×1152 | 불필요 | 〃 |

원경 레이어다. 화면 높이에 맞춰 그려지고 카메라의 35% 속도로 흐른다.
해초·바닥은 코드가 따로 그리므로 배경에는 넣지 않아도 된다.

### 3-3. 플레이어 상어 (`assets/shark/`)

진화 4단계마다 따로 그린다. 키는 `shark.<상어id>.<단계 0~3>`.

| 상어 id | 이름 | 파일 |
|---|---|---|
| `reef` | 리프 샤크 | `reef_0.png` ~ `reef_3.png` |
| `saw` | 톱상어 | `saw_0.png` ~ `saw_3.png` |
| `hammerhead` | 귀상어 | `hammerhead_0.png` ~ `hammerhead_3.png` |
| `mako` | 청상아리 | `mako_0.png` ~ `mako_3.png` |

단계 0=치어 / 1=유어 / 2=기본 / 3=성체. 권장 1024×683, 투명 필요.
단순 확대가 아니라 단계마다 실루엣이 달라지게 그린다.

### 3-4. 물고기 (`assets/fish/`) — 29종

키는 `fish.<id>`, 파일은 `<id>.png`. 권장 512×342, 투명 필요.

**햇살 연안** `anchovy`(멸치) `shrimp`(새우) `clown`(흰동가리) `mackerel`(고등어)
`puffer`(복어) `seabass`(농어) `crab`(게) `ray`(가오리) `barra`(바라쿠다) `jelly`(해파리)

**산호 정원** `parrot`(비늘돔) `butterfly`(나비고기) `wrasse`(청줄놀래기) `lionfish`(쏠배감펭)
`striped`(돌돔) `squid`(오징어) `moraykid`(곰치 치어) `reefpup`(상어 치어)
`clam`(대왕조개) `urchin`(성게)

**난파선 해구** `sardine`(정어리) `yellowray`(노랑가오리) `angler`(아귀) `conger`(붕장어)
`tuna`(참치) `swordfish`(황새치) `hammer`(귀상어) `blueshark`(청새리상어) `mine`(기뢰)

`jelly` `urchin` `mine` `clam` 은 회전하지 않는다 — 똑바로 선 모습으로 그린다.
나머지는 전부 오른쪽을 보게 그린다.

### 3-5. 보스 (`assets/boss/`) — 3종

| 키 | 파일 | 이름 | 비고 |
|---|---|---|---|
| `boss.giant_barra` | `giant_barra.png` | 거대 바라쿠다 | 권장 1536×768 |
| `boss.giant_moray` | `giant_moray.png` | 대왕 곰치 | 〃 |
| `boss.rogue_white` | `rogue_white.png` | 무법자 백상아리 | 〃 |

보스는 가로폭 = `len × 1.3` 으로 그려진다 (일반 생물보다 여유가 적다).

## 4. 이미지를 써도 유지되는 것

그림으로 바뀌어도 아래 게임 규칙 표시는 코드가 계속 그린다.

- **티어 외곽선** — 먹이(없음) / 동급(노랑) / 포식자(빨강) / 껍질(하늘)은
  스프라이트 주위에 타원 링으로 표시된다
- **보스 경직 고리** — 노란 점선
- **보스 부위 발광** — 머리 빨강 / 꼬리 초록 (Canvas 폴백에서만. 스프라이트에는 직접 그려 넣는 편이 자연스럽다)
- 체력바, 흡입 반경, 파티클, 어두운 해역 시야 제한

---

## 5. 성능

- 이미지는 부팅 시 1회만 로드하고 재사용한다. 매 프레임 생성하지 않는다
- 파일 하나당 300KB 이하를 권장한다. 29종 + 배경을 모두 넣으면 합계가 커진다
- 모바일에서 과도한 해상도는 메모리를 먹는다. 위 권장 크기를 넘기지 않는 편이 좋다
